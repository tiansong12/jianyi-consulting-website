02 / METHODS

工作方法

方法不是先写出来的标准答案。它来自多项工作里反复出现的问题、取舍和验证方式，并保留适用条件。

阅读顺序

诊断问题 → 定义边界 → 推进项目 → 小范围验证 → 回到证据复盘。

01诊断

从经营问题判断系统建设边界

适用于

一个经营问题究竟应该改流程、改责任、改数据，还是建设系统？

核心动作

把现象改写成管理者需要回答的问题 → 识别涉及的角色、流程、数据和利益关系 → 区分系统可解决、需组织改变和暂不具备条件的部分 → 形成范围、依赖和不做事项

02定义

从现状调研形成业务蓝图

适用于

怎样把不同部门的说法转换成一份可以实施和验收的共同定义？

核心动作

按角色和业务事件访谈，不只按系统模块提问 → 记录现状动作、凭据、等待、返工和例外 → 将问题定位到流程、规则、数据或责任 → 设计目标流程并明确阶段范围和验收条件

查看方法 →
03诊断

按约束强弱判断数据可信度

适用于

数据不完整时，哪些指标还能用于行动，哪些只能提示风险？

核心动作

识别强约束数据，例如交易与结算 → 识别需要抽核的中约束数据 → 标出依赖人工、容易漏记的弱约束数据 → 让分析输出与证据等级对应

查看方法 →
04验证

用小范围试点和约束指标验证方案

适用于

怎样在投入扩大前判断一个方案是否真的值得继续？

核心动作

选择问题明显且具备基本条件的对象 → 明确基线、动作、负责人和记录负担 → 设定结果、约束与执行指标 → 按固定节奏复盘，并预先约定扩大、调整和停止条件

查看方法 →
05推进

用责任、里程碑、风险和验收推进多方项目

适用于

当业务、IT、供应商和管理层目标不同，怎样让项目持续向前？

核心动作

明确项目目标、范围、角色和决策机制 → 把关键依赖纳入阶段门 → 持续管理问题、风险、变更和待决策事项 → 在测试、切换、验收和交接前逐项检查条件

查看方法 →
06复盘

从案例提炼经营机制，而不是照搬功能和结果

适用于

怎样让外部案例帮助理解自己的问题，又不制造错误类比？

核心动作

先确认来源和案例发生的条件 → 按问题、冲突、行动、机制和结果整理 → 区分事实、案例方解释、个人推断和建议 → 把案例转成听众可以自查的问题
