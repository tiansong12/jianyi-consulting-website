从经营问题判断系统建设边界

一个经营问题究竟应该改流程、改责任、改数据，还是建设系统？

先定义需要改变的经营动作，再判断技术在其中承担什么角色。

方法步骤

  1. 01

    把现象改写成管理者需要回答的问题。

  2. 02

    识别涉及的角色、流程、数据和利益关系。

  3. 03

    区分系统可解决、需组织改变和暂不具备条件的部分。

  4. 04

    形成范围、依赖和不做事项。

适用场景

  • 系统规划与选型
  • 门店数字化项目
  • 复杂经营问题诊断

使用边界

  • 缺少业务负责人时，系统边界无法真正确认。
  • 不能用功能清单代替现场事实。
